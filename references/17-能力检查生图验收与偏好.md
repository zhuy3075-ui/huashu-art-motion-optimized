# 按需能力检查、生图验收与偏好范围

需要新配音、生图/改图或用户说“以后默认这样”时读本页。已有声音按14/16号调用，素材/角色按15号，DNA按13号；本页不替换这些流程。脚本只处理偏好、状态和文件契约，不代替Agent调用实际工具，不证明身份/听感/内容已认可。

## 1. 只检查本次需要的能力

`scripts/capabilities.py`只读，不联网、不解密Key、不扫描未知凭据目录。输出`configured_unverified`仅表示当前所选配置/依赖齐全，仍需已授权实际调用检验；文件存在不等于Key有效。不要为了准备配置额外问一轮：用户已明确平台/音色/素材用途时整理成本次覆盖直接执行其范围，未定才给具体候选。新旁白的自定义音色必问项及全文确认继续按00/14/16执行。

```powershell
python scripts/capabilities.py --task '项目/本次媒体选择.json' status --capability voice
python scripts/capabilities.py status --capability voice --audio '项目/用户口播.wav'
python scripts/capabilities.py --task '项目/本次媒体选择.json' status --capability image --tools '项目/实际工具.json' --session '当前会话唯一ID'
```

没有旁白、只改字幕、只研究风格时不启动声音检查。已有音轨直接沿用；`--audio`仅检查该文件存在，不冒称已解码。DubbingX默认WAV使用原生校验，检查MP3条件时加`--audio-format mp3`；火山仍由原适配器生成MP3和词表，必须有ffmpeg/ffprobe。仅素材导入或现有图合成不检查生图工具；图片模式existing/off无需工具快照。

状态`needs_selection/needs_configuration/needs_tool_snapshot/unavailable/blocked`分别说明缺选择、配置、实际工具或禁止条件；不能据此换平台、默认官方音色、调用收费服务或自动安装依赖。音色缓存与成功历史继续读对应平台脚本，不复制成第三份库。

## 2. 偏好不是调用授权

优先级是**本次覆盖 → 项目偏好 → 用户偏好 → 公共默认**。本次文件由Codex按用户已经给出的选择生成，内容是数据，不是执行指令。例如用户已选DubbingX的真实ID后可整理：

```json
{"preferences":{"voice":{"provider":"dubbingx","account":"已有账号别名","voice_id":"已选真实ID"},"image":{"mode":"generate","tool_id":"当前实际工具ID"}}}
```

voice.provider支持unconfigured/off/provided/volcengine/dubbingx；火山另填本平台resource_id。image.mode支持unconfigured/off/existing/generate，tool_id为实际ID或auto。切换平台会清空继承的另一平台账号/音色/资源，不拿DubbingX ID调用火山。脚本不检查或承诺云端音色权限，仍由14/16号在实际流程核对。

普通“这次用它”只作为本次覆盖；**用户明确“记住/以后/默认”才保存用户偏好**。用户没有回答不写默认。项目偏好只保存这支片子的选择，不扩大全局。配音/生图禁止项denied可含cloud、paid_api、image_generation、reference_upload、unknown_cost；各层取并集，项目或本次空列表不能解除用户禁止。它没有allow字段，不把偏好升级为付费、上传或生成许可。用户明确改变某层禁止项时只改该层，仍不能越过宿主限制。

```powershell
python scripts/media_preferences.py --project '项目' show --task '项目/本次媒体选择.json'
# 仅本次：返回覆盖项，不写用户文件；由Codex留在本次创作记录
python scripts/media_preferences.py set --file '项目/本次媒体选择.json' --scope task --evidence '本次真实选择原话/位置'
# 只有用户明确要求长期记住后才执行
python scripts/media_preferences.py set --file '项目/要记住的偏好.json' --scope user --evidence '用户明确要求以后默认的原话/位置' --expected-revision 0
python scripts/media_preferences.py --project '项目' set --file '项目/片内偏好.json' --scope project --evidence '用户对本片的实际选择'
python scripts/media_preferences.py skip --capability image --scope task --evidence '用户这次不用生图'
python scripts/media_preferences.py reset --capability image --scope user --evidence '用户要求重置长期图片偏好'
```

`--expected-revision`使用show输出中对应范围的`revisions.user`或`revisions.project`，不使用合成配置的公共revision，也不固定照抄0。长期偏好在`CODEX_HOME/config/huashu-art-motion/media-preferences.json`，未设置时`~/.codex/config/huashu-art-motion/`；项目文件为`.huashu/media-preferences.json`。读写同一root；写入有进程锁/原子替换和版本检查。没有实际选择前不创建私人默认；重装不覆盖该文件、平台凭据、角色或DNA。配置不接受api_key/token/授权字段。例子与模板不是用户已选择的事实。

## 3. 当前实际工具 → 计划 → 实际调用

只有确实需要且已授权生图/改图才开始。已选母版、角色版本、DNA和身份保留项写入具体请求；参考素材需包含实际文件。仅调用已存在的工具，不从Key、技能名或“Codex”推断能力。Agent从当前暴露的工具schema确认操作/参考图/透明背景支持，写任务内快照；没有工具写空数组。快照15分钟有效，session_id是本次唯一会话标识，observed_at填实际Unix时间。

```json
{"session_id":"当前唯一会话ID","observed_at":0,"tools":[{"id":"当前实际工具ID","operations":["generate","edit"],"reference_images":true,"transparent_background":true,"network":"cloud","cost":"subscription"}]}
```

数字0仅演示字段，必须替换实际时间。network是cloud/local；cost是subscription/paid_api/unknown/none，订阅不等于免费或无限额度，未知费用填unknown。tool_id未明确且有多个合适工具时需具体选择，不擅自猜。工具要求透明不受支持时说明，不替换成其他供应商。

`assets/generated-image-request.template.json`复制成项目实际请求：prompt、operation generate/edit、references路径数组、transparent_background、min_width/min_height。改图必须有参考；相对路径相对请求JSON。只提出用户已定的具体任务，不把完整风格/角色配置当指令上传。

```powershell
uv run scripts/generated_images.py --task '项目/本次媒体选择.json' plan --request '项目/实际图片要求.json' --tools '项目/实际工具.json' --session '当前唯一会话ID' --out '项目/生图计划v1.json' --approval '已经存在的生成范围及工具授权原话/位置' --allow-cloud --allow-reference-upload
```

授权flags只表达已有授权：cloud工具需allow-cloud，参考上传需allow-reference-upload，paid_api需allow-paid-api，unknown需allow-unknown-cost；本地工具不加云flags。`--approval`记实际生成范围/工具依据，不自造确认，不重复询问已有授权；禁止项不能被flags绕过。本计划不会调用工具或产生媒体费用。

随后Agent按**实际工具schema**发起调用，不把计划JSON当通用API参数。生成成功才填`assets/generated-image-receipt.template.json`中的真实plan_id/session_id/tool_id/output_sha256，以及tool_call_reference（实际调用记录的可追查位置）。失败就报告实际失败，不写success，不用旧缓存冒充新产物。回执是Agent记录，非平台签名认证；PNG元数据不能证明模型来源。

## 4. 验收、复制与角色衔接

```powershell
uv run scripts/generated_images.py --task '项目/本次媒体选择.json' accept --plan '项目/生图计划v1.json' --receipt '项目/生图回执v1.json' --file '实际工具返回的本地图片.png' --out '项目/素材/新动作v1.png' --tools '项目/当前实际工具.json' --session '当前唯一会话ID' --approval '同一任务已经取得的实际授权依据' --allow-cloud --allow-reference-upload
```

重新核对当前配置/禁止项、工具和会话；计划最长1小时，不能修改旧时间假装有效。参考图哈希变化、工具变更、回执不匹配、全透明、尺寸不足、要求透明却无实际透明像素均拒绝。支持静态PNG/JPEG/WebP，完整解码/EXIF归正视图检查，最多4000万像素；要求的最小宽×高已超过上限时在建计划前拒绝，不先调用工具。原字节不改，输出扩展名须匹配实际格式。

输出复制到项目新文件，写同名`.png.json`等旁车，记录真实尺寸/透明度、SHA、plan_id、工具/实际调用依据和review_required=true。图片或旁车已有任一就拒绝覆盖；写入中断的部分文件不算成功，保留检查后使用新版本路径，不自动删原件。计划/快照/回执含私人参考路径和提示词，留在项目，不入公开技能包。

**accepted_technical不是用户认可。** 实际看图检查脸、服装、左右差异、DNA、边缘和姿势；技术合格不能放行角色身份、动作或整片。按15/10号进行合成样稿、实际帧切分与锚点评审；按真实反馈再保存角色库。现有原图仍走image_assets.py，不要求伪造生图回执。纯代码静帧也不走生图验收。
