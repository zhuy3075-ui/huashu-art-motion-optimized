# 18 · 批量创作与调用

用户要系列片、多个选题、同一模板的不同内容或继续上次批量任务时读本页。批量是复用制作流程和已选资产，每支片子的实际内容仍单独确认。只做一个局部修改不建队列。

## 一、先确定批量范围

先从用户已有列表/素材提取任务，不要求手写 JSON。给一个清晰清单：任务ID、选题、素材位置、受众/用途、预计规格、共享风格/角色/音色与单项例外。按素材追问最影响结果的取舍，例如：“这三篇素材都在解释同一概念；你希望做一组连续看的系列，还是每支都能独立看懂？前者可共用开场，后者需要逐支补背景。”

展示清单后**实际询问**：“请确认这些选题与共用配置；哪些条目需要不同画风、角色或声音？”清单确认只授权建任务和起草，不确认尚未展示的文案。已有素材/风格/声音选择沿用，不重复问；新旁白的自定义音色必问项仍按00/14/16执行。普通共享配置只留本项目，不写全局默认。

数量、平台、音色、调用范围或成本边界未定时，先起草清单和文案。确认调用范围后再生成已授权条目的媒体；逐支实测时长与实际调用记录汇总，不能编造总价。并发付费生成、后台定时或无人值守不在本页实现范围。

## 二、本地队列

将[清单模板](../assets/batch-creation.template.json)复制到项目并替换示例，使用[scripts/batch_creation.py](../scripts/batch_creation.py)。脚本只读写项目状态，不联网、不读密钥、不运行 shell 或模型 API。**实际创作由当前 Codex 会话读取 `next` 的任务，按本 skill 调用现有制作工具。** 它不是单独运行就能生成整批视频的程序。

清单字段：`schema_version=1`、`name`、`defaults`、`jobs`（1–100项）。每项 `id` 为唯一小写英文ID，`topic`写选题与素材位置，`settings`覆盖共享配置。配置仅支持 `style_ref`、`character_ref`、`notes`、`voice`；声音仅支持 `provider/account/voice_id/resource_id`，没有凭据/命令/自动授权字段。风格与角色实际读取后按13/15号固定版本；空值表示尚未选定，不能自行造档案。跨平台覆盖会清空旧音色ID、账号及资源绑定。

所有状态、阶段产物与历史留在**项目内** `.huashu/batch.json`、`.huashu/batch/jobs/<id>/`，不写安装包或公开仓库。素材原件按15号另行保留。阶段产物用新文件名，不能覆盖旧版；`finish`还保存独立 `.versions/`快照，防止后续覆盖原路径丢失已记录文件。媒体评审可用包含实际视频/音频/截图链接、哈希与验收记录的 Markdown 清单；队列仅备份传入文件，清单引用的视频/音频仍需另存版本。

```sh
python scripts/batch_creation.py --project "我的系列工程" init --file "我的系列工程/选题清单.json"
python scripts/batch_creation.py --project "我的系列工程" status
python scripts/batch_creation.py --project "我的系列工程" next
```

恢复时读取 `status`、实际产物、用户最近回复，再调用 `next`。已有队列禁止覆盖初始化。`next`只读返回当前可做事项，没有后台执行器；结束会话后需用户再次调用技能续做。

## 三、每阶段都有真实确认提问

每支片子有七个节点：`brief`简报、`outline`大纲、`script`完整文案、`storyboard`分镜与视觉、`voice`声音方式/具体音色和生成范围、`pilot`短样片、`film`候选整片。

1. `next`返回 `create` 时，核对前置产物与本项实际授权，领取该阶段：

   ```sh
   python scripts/batch_creation.py --project "我的系列工程" start --job episode-one --stage brief --reference "episode-one/制作记录.json" --expected-revision 1
   ```

   保存返回的 `operation.token`，在 `reference`所指的本任务记录中保存实际工具调用引用、稳定请求ID/平台 task_id、输出路径及授权范围。云端提交前先写请求ID；已有任务只查询/下载。队列 token 不是平台 task_id，也不能充当生成授权。

2. 由 Codex 完成这个阶段，保存实际产物，再结束领取：

   ```sh
   python scripts/batch_creation.py --project "我的系列工程" finish --job episode-one --token "实际返回的token" --artifact "brief-v1.md" --tool-reference "真实制作记录位置" --expected-revision 2
   ```

   `artifact`必须是该任务目录内存在的非空文件，返回产物 SHA256 和版本。`finish`只标为待确认，不能继续本任务的依赖阶段。

3. 展示可读产物/可播放样片、任务ID和版本，按[19号](19-Codex提示词与阶段确认.md)提出具体确认问题。用户回复后才保存确认；预选、超时、没有回复、工具成功均不算确认。

   将**已经实际展示且用户明确认可**的确认对象写进项目 `确认列表.json`，格式如下。哈希从最新 `status`取实际值，不用示例。

   ```json
   [{"job_id": "episode-one", "stage": "brief", "sha256": "此处替换为实际64位SHA256"}]
   ```

   ```sh
   python scripts/batch_creation.py --project "我的系列工程" confirm --file "我的系列工程/确认列表.json" --evidence "用户针对这些版本的确认原话" --source "真实对话位置" --expected-revision 3
   ```

   脚本能绑定文件版本，不能识别用户身份或证明对话真伪；Codex必须引用真实回复，不能自己写“用户已确认”。00号允许的明确委托仍按其范围沿用：产物实际存在后将真实委托原话和范围记录为依据，不能扩大为自定义音色、额外收费或发布授权。

4. 再读 `next`继续。一个任务待确认时，可以起草另一个任务的简报或文案；始终只领取一个运行中操作。全部任务待确认/被阻断时集中展示待确认清单并结束本轮，不能轮询等同意。

**批量确认可合并同阶段的多个已展示对象。** 例如展示A/B/C三份全文，问“是否采用A文案v2与B文案v1？C的结尾要保留故事还是换成总结？”只把用户明确认可的A/B加入确认列表。用户说“这三份全文都可以”且对象唯一明确时，可一起确认；一项哈希过期则整次确认拒绝，不部分放行。不要将“这几条选题不错”解释为整批全文/样片都通过。

无旁白仍记录 `voice.provider=off`，声音节点说明无旁白、字幕和音乐安排；沿用原音频用 `provided`并在评审产物中引用原件。新旁白未确定平台、账号和音色不能进入样片；火山还须真实 `resource_id`。声线/试听/正式合成授权分别记录，声音节点不默认授权整批长配音。

## 四、失败恢复与修改

- 返回 `recover_operation`：先查已保存恢复记录与原平台 task_id；不能再次提交。完成原操作后使用**同一个token** `finish`。
- 外部调用超时/状态未知：用 `fail --job <id> --token <token> --evidence <原因> --expected-revision <当前值>`保存未知状态，原操作保留并继续占用串行领取；先查询原任务，不能启动另一条生成。
- 已核对原平台确定Failed/Canceled终态，才可给 `fail`增加 `--terminal`，将该项隔离并继续其他任务。原操作引用保留；`fail`不是“未产生费用”的证明。
- 失败后原任务成功：按原任务查询/下载，再用同一个token `finish`，不创建新任务。
- 确认原任务终态、决定放弃或重做时，先记录平台查验结果和用户已授权的处置范围，再 `resolve --job ... --token ... --evidence ... --expected-revision ...`归档原操作；它只解除本地领取，不取消云任务、不重试、不授予新付费权限。
- 返回 `stale_artifact`：实际文件缺失/改变，不能沿用旧确认。解决在途操作后 `invalidate --job <id> --stage <受影响节点> --evidence <改动依据> --expected-revision <当前值>`，该节点及后续进入历史，旧文件保留；重出版本、重新确认。
- 改配置：`settings --job <id> --file <覆盖配置.json> --evidence <实际改动依据> --expected-revision <当前值>`。`notes`变更回退简报及后续；风格/角色变更保留全文、回退分镜及后续；声音变更保留分镜、回退声音/样片/整片。若声音变化影响阅读停留或分镜节拍，再按实际影响回退分镜。在途操作不能直接修改。

`expected-revision`必须使用最新状态值；陈旧写入会被拒绝，重读后再决定动作。历史不用于自动恢复旧授权。成片阶段的评审文件包含真实文件哈希、实测规格、数字 QA/独立审片结果与未做检查；用户确认候选后才标完成。队列记录不替代14/16的音频有效性、17的生图验收及整片质量检查。
