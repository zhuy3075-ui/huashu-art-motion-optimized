# 00 · 帮用户逐步完善需求

本页负责从想法到开工的创作协作。用户不需要先写专业需求书；技能负责提炼、给选择、写草稿和解释效果，用户决定讲什么、给谁看，以及关键内容是否采用。具体绘制、音频和验收仍按原制作文档执行。

用户先拿参考帧找画风、整理自己的风格或保存本地风格时，进入[13号Style DNA](13-Style-DNA与本地风格库.md)，不要求先确认整片文案。详细风格档案/提示词可先研究和保存；文案制作与确认仍在实际新片开始后按本页推进。

## 一、先给参考，再反问追出需求

用户说不清楚时，先把主题和素材转成看得懂的创作可能性，再邀请他比较和修正。这里的“反问”是带着理解与假设的探索式追问，不是“难道你不觉得”的质问，也不是用推荐答案诱导用户同意。

### 提问前先看见素材

读取用户给的文字、音频、图像、视频或参考链接中与任务相关的内容。用一两句指出具体线索：反复出现的概念、关键转折、独特经历、视觉特点或素材缺口。明确区分“素材写了什么”和“我推测你可能想突出什么”。不要没有读素材就问用户把内容再讲一遍；无法访问时说明缺口，不假装看过。

没有素材时，从主题与用户原话提炼可比较的讲述方向，说明目前只是候选。确实需要用户补充的信息用一个具体问题取得，不让用户先交专业需求书。用户已说清的目标、规格和选择直接沿用。

### 给本次任务的方向参考

为当前关键取舍设计通常2–3个有实质差别的方向；数量服从任务，不是每轮固定三选一。选项按用户素材生成：素材是亲历故事就比较人物视角与转折，素材是发布记录就比较时间线与能力变化，素材是抽象机制就比较一个例子与推导链。沿用用户用词，不固定列“科普/宣传/故事”或“白板/Vox/发布会”。

每个方向用短描述给出足以判断的参考，按需要包含：

- **怎么讲：** 切入角度、会使用的素材、观众最终记住什么。
- **能想象的片段：** 一句示意开场、一个具体画面或一段微型分镜；标明它是探索草稿，还不是待制作的定稿。
- **为什么适合/要舍弃什么：** 解释与本次素材的联系及信息密度、情绪或制作代价的取舍。

用户需要的是方向判断时，可以先用文字画面、已有素材片段或可访问的参考帮助理解；不必为了提问就生图、渲染三套样片。引用外部参考时说明具体借鉴点，有链接就读取核实，不冒称看过。最终风格设定稿仍在内容放行后按03号制作。

### 用反问检验假设，逐轮更新

一次抓当前一个主要分歧，把素材观察、假设和选择连起来，例如：

- “你给的三段经历都有一次失败后的转变；如果用失败做开头，你更想让观众代入你的经历，还是马上学到解决办法？前者适合故事线，后者适合问题→方法的讲法。”
- “这份资料列了很多发布时间，但变化最明显的是能完成的任务；如果只留下三个阶段，你更希望观众记住年份，还是看懂能力怎样升级？要不要先用同一个任务比较三个阶段？”
- “你选了轻松，但素材里的专业概念比较密；如果先用一个生活例子讲清主线、把术语留到后半段，会更接近你说的轻松吗？还是你希望保留技术细节，靠画面来减轻负担？”

以上是问法示例，不能照抄成所有主题的固定选项。推荐可以有，但说明依据，允许用户混合、修改或拒绝选项；不要将假设说成用户既定意图。问“是不是”时同时提供有意义的另一种方向，不能只留下顺着你回答的路。

收到回答后先简短反映新理解，再提出由这次回答引出的下一项取舍。例如“想给新人看”使下一问转向哪些概念应保留、用什么例子解释；“给同行看”则追问技术深度或证据。用户只说“都不太对”时，追问具体不对的地方并换方向，不反复展示同一菜单。

用户已给足信息时，直接把理解写成简报或当前阶段草稿供确认，不为了完成问卷凑轮数。提问的成功标准是得到能指导下一份产物的内容，不是完成几个问题或几次选择。

## 二、进入哪一步

先读用户现有材料和最近确认，判断哪些信息已经给出、哪些只是建议。每阶段聚焦少量最影响下一步的问题，通常1–3个；信息齐全就提交该阶段产物，省去采访。不要仅凭“科普/艺术/历史”类型选择就启动整片。

| 当前请求或材料 | 起点与必要边界 |
|---|---|
| 参考帧识别风格、个人风格整理、查阅/保存已有风格 | 走13号独立分析/风格库流程；不启动整片，不先采访全部内容规格 |
| 只有主题、模糊想法或要求代写 | 从需求简报开始；之后逐步确认大纲和完整文案 |
| 已有明确需求与批准的大纲 | 沿用需求，起草完整文案并确认 |
| “按这份文案做”并提供全文 | 将原文记为已授权使用，不重问大纲；补齐影响制作的缺项，进入分镜与画风 |
| “用这段口播配动画”并提供音频 | 沿用音频，不擅自改文案或重新配音；整理转录与镜头表。影响含义的转录歧义需澄清 |
| 指定参考图、明确选定的画风 | 沿用视觉方向，不强制重选三套；新角色或未定的视觉诠释再做比较 |
| 明确调用本地Style DNA | 读取选中版本，固定ID/版本与本片覆盖项；沿用已确认风格，继续确认尚未明确的内容 |
| 只拆解参考片或只咨询方案 | 交付拆解或方案，不启动生图、配音或整片制作 |
| 固定文案、时长和画风的单片段 | 核对已给条件后直接做该片段，不扩展成整片采访；缺项按影响程度补齐 |
| 改一句字幕、颜色或某个镜头 | 只处理局部改动，复验受影响项；不重走全部流程 |

参考片和工程示范中的主题、角色、音色、时长不自动成为新片需求。不要默认用户拥有其他视频管线、付费服务或角色素材。

用户给图片/角色时先按[15号](15-用户素材与角色库.md)实际看图并给编号，解释原样合成、仅作参考或允许改绘的具体效果；已明确选择不再问。身份保留项、裁切/去背景/材质处理和缺失动作记录在素材清单或角色卡；原件保留、处理另存。仅素材导入、角色建档可以独立进行，不能以素材整理为由启动正式配音或整片。

## 三、默认阶段与交付物

### 1. 需求简报：先知道这支片子要达到什么效果

先沿用已给的受众与效果，只补当前缺失的关键取舍。受众确实未知时，可以反问“给刚接触的人认识它，还是给已在用的人梳理变化？”，并按主题和素材提供具体参考、推荐及理由。再补会改变内容的重点、使用场景、时长限制和素材；不要求用户解释渲染器或镜头术语。

逐步形成一份短简报：主题、受众、观看后应理解的事、内容重点与不讲的内容、发布场景/画幅、目标时长或上限、旁白/字幕/配乐意向、已有材料与禁忌。把未定项标为“建议”或“待定”；可先给合理建议供用户整体确认，后续细化音色和画风。

**需要新生成旁白时，需求阶段必须询问是否使用用户的自定义音色以及具体选择。** 先沿用已选平台；未定时结合用户已有库和字幕需求提供火山/DubbingX选择。按[14号火山](14-火山TTS与逐字字幕.md)或[16号DubbingX](16-DubbingX异步配音与音色历史.md)展示所选平台本账号历史成功名称/ID与真实试听，再提供火山控制台导入候选或DubbingX真实云端候选；不能只有“男声/女声”选项，不把历史生成当用户认可，不默认换官方声音。已明确选择直接记录，不重复问；原口播沿用、无旁白或仅风格分析不重配。简报可在声音待选时继续完善大纲，但不得开始合成，声音选择在需求过程补齐。

**离开条件：** 用户确认简报中影响大纲的内容和规格，或明确将相应决定委托给你。不要凭提问数量判断需求已完整。

### 2. 内容大纲：先确认讲述方向

给出标题或开场方向、3–6个内容段落、每段要讲清的一件事、结尾落点，以及预计时长分配。按片长调整段落数，不把历史片自动写成全部年份的流水账。存在明显不同角度时先给可比较的大纲方向。

历史、产品、科学或数字内容先核对可靠来源，区分事实和解释，标出会影响文案的疑点。研究不能替用户决定重点，不能把未核实推断写成确定事实。

**离开条件：** 用户选定/确认这个大纲。批准大纲只允许写完整文案，不等于批准文案、声音或画面。

### 3. 完整文案：必须看到实际要说的话

提交可审阅的全文，包含开头、全部主体、过渡和结尾；标注文案版本、字数、预计口播时长及核心标题/画面文字。长文可保存为文件并打开或链接，但不能只发路径、摘要或“文案已写好”；让用户实际能够阅读内容。重要事实给出处或附简短核验说明。

以一个明确对象收尾，例如“请确认文案v1；确认后我会做分镜与画风样张。也可以直接指出要改的段落。”用户提出修改时先展示修改后的版本，不能把修改意见当作新全文已经通过。

**离开条件：** 用户明确批准实际展示的全文版本，或明确授权你自行定稿且无需再审。未通过时可以修改文字或查资料；不得生成正式TTS、批量素材、完整动画和整片渲染。不能在同一轮展示待审文案后，立即调用这些工具。

“没有旁白”不等于“没有内容关卡”：确认将出现在画面上的标题、字幕、说明和叙事安排。无文字的纯艺术片可用简短动作/叙事说明合并大纲与文案关卡，不硬写口播。

### 4. 分镜与画风：确认内容怎样变成画面

依据已确认文案制作镜头表：段落/时间范围、对应原句、画面在解释什么、主动作与转场、核心画面文字。不要在分镜阶段自行增删观点、重写旁白。短片可展示全表，长片先给整体结构与代表镜头，完整表需可查阅。

未定的新方向用同一句文案的同一镜头做三张设定稿，清楚标A/B/C，说明不同的叙事效果和制作取舍，给出推荐。已选定参考或已确认的本地Style DNA直接沿用，不重选三套；遇到新的角色诠释或视觉冲突按需比较。用户不懂“Vox”“Keynote”时用“档案拼贴”“科技发布会”这样的效果描述。只比较画风，不同时更换文案、构图主题和故事重点。03号继续提供设定帧方法。

用户选定自己的图片或角色时，先给使用实际素材的合成静帧，说明缩放、脚底位置、裁切、字幕区和材质处理；新动作给短循环检查身份与漂移。沿用已确认母版/角色版本无需强制重新生成三套。素材样稿认可只放行该素材处理范围，不替代整片全文、声音或全片确认；仅素材建档则按15号保存状态结束。

**离开条件：** 用户确认分镜方案和视觉方向，或已有明确授权。仅选择C画风时，只记录画风选择；未展示或未批准的分镜、文案仍待确认。用户只批准代表镜头时，可以按已授权结构完善其他镜头；改变结构或加入新内容仍需确认。

### 5. 短样片：确认动起来和听起来的效果

先做约5–10秒或一个有代表性的完整镜头，检验动作、节奏、可读性和画风，不先渲整片再称为样片。需要旁白时，以已确认文案的片段试音，给可播放音频或带声样片；标明音色、语速、字幕与音乐方案。用户已有音频则直接沿用。

新配音先核对已选平台、账号、声音来源、具体音色ID与平台参数、语速/读法和本次生成授权；缺声音选择先问，不自动开始。火山按14号取得同任务有效MP3与真实词表/SRT，超时恢复原task_id，音频与时间轴全部校验后进入历史。DubbingX按16号查询选中voiceId和情绪，提交/恢复原任务，下载有效WAV或MP3后记历史；它不返回字级时间戳，字幕和关键词动作需对这条音频实际转录/对齐，缺能力先说明并停在相应环节。不得复用另一平台时间轴、按字数均分或为了取字幕另合成一条火山音频。试听与整段生成授权分开，试听意见不自动放行整段。

把候选音色描述为听感和用途，不让用户先研究音频工具。若配音能力不可用，说明具体缺口、给实际可行的交付选项，不悄悄换成用户没选过的声音。费用或外部服务权限按当前环境授权边界处理。

**离开条件：** 用户确认样片效果，或明确跳过样片/委托直接制作。样片意见先在该镜头修正；不能把“更慢一点”当作对未展示的整片放行。

### 6. 整片与验收：按已确认方案完成

整片制作前核对文案、分镜/视觉、声音、画幅和时长约束的最新状态。正式配音若明显超出约定时长或上限，先提出删减/调整方案并确认受影响内容，不能擅自加速、删稿或延长；预计时长不能冒充实测时长。

制作、QA与独立审片按SKILL.md、09/12号执行。通过技术检查后交付候选成片，说明实测规格、已做和未做的验证及剩余问题。用户选定候选后冻结版本；候选可交付，但不能把技术检查通过写成用户已认可创作效果。

## 四、确认与委托怎么解释

- 确认针对**实际展示的产物和版本**。上文只有一个明确待确认对象时，用户针对它的“好，就按这个来”可算确认；混着简报、文案、分镜时，一句含糊“好的”不能放行所有阶段。
- “请帮我做”“文案你写”“你推荐一个”“先给我一版”分别授权协作、起草、推荐、候选，不能据此省掉关键确认。不要追问已确认项。
- “文案由你定，不用确认”免去文案关卡，仍不扩大为画风、声音或其他事项的委托。“全部由你决定，不用再问，直接做成片”授权整片创作决定，可按合理假设推进；**新配音的自定义音色必问项仍按所选平台14/16号执行**，直到用户已选定声音或针对具体音色候选明确委托。记录假设和授权范围，仍遵守实际工具权限、费用边界和质量检查。
- 明确要求合并阶段时，展示可审阅的联合产物并按其授权执行。不能自己把“快一点”解释为跳过文案确认。
- 必须等待的确认发出后，未收到回复就保持待确认。异步工具已接受请求、预选推荐项、超时或没有答案，都不能推断同意；可结束本轮，说明当前待确认对象与下一步，不轮询催促。
- 解释等待时，给出具体下一步与确认对象；若需要说明技能关卡，链接本页对应阶段并引用相关离开条件，不泛称“安全规定”。

## 五、状态与变更

多轮项目优先沿用已有项目文档，否则在项目内维护一份`创作确认.md`。短咨询或局部改动可只记在对话，不强制创建多份文档。只写必要状态，用户私人材料留在项目内。

```markdown
# 创作确认
- 当前阶段：文案v1待确认
- 需求简报：已确认，依据：用户原话或对话位置
- 大纲：v1已确认
- 文案：v1已展示，待确认（可读链接）
- 分镜与画风：未开始
- 样片与声音：未开始
- 新配音音色选择：待询问／已明确，平台、来源、该平台账号别名、音色ID（火山speaker/resource_id或DubbingX voiceId）、参数/读法、试听状态与依据
- 明确委托：无／原话及范围
- 下一步：收到文案确认后制作分镜与设定稿
```

恢复任务先读取最新记录和用户回复，能看到可读产物但没有确认依据时，只补当前缺失的确认。不把模型自写的“通过”、工具成功或文档标题“定稿”视作用户批准。

变更只回退受影响部分：改文案的观点/顺序使对应分镜、配音和样片需更新；换画风不使已批准文案失效；改错别字或用户明确指定的局部修改直接执行并复验。对已批准全文有实质性新增、删减或改写，展示新版本重新确认，除非在明确委托范围内。

## 六、首次引导示例

用户：“帮我做一支讲Codex发展史的动画。”

先说明：“我会先帮你把讲述方向找出来，给你大纲和完整文案；确认后再做分镜与动画。”用户尚未给素材时，提供针对这个主题的探索参考，例如：

| 候选方向 | 具体参考 | 适合的效果 |
|---|---|---|
| 按重要发布节点讲 | 示意开场：“每次发布，究竟改变了什么？”画面是一条时间线，每个节点只出现一项变化 | 想把发展过程按顺序梳理清楚；需要核实年份和发布记录 |
| 用同一个编程任务比较变化 | 示意开场：“同一道任务，在不同阶段会怎么完成？”用同一个任务场景对照操作过程 | 给陌生观众具体感受；需先核实各阶段实际能力，不能虚构演示 |
| 围绕开发者工作方式的变化讲 | 示意开场：“写代码这件事，哪些步骤开始交给工具了？”用人和工具之间的任务交接作画面 | 更强调使用者视角；需要具体工作经历或场景支持 |

随后反问：“你说‘发展史’，更希望观众记住重要节点，还是看懂它改变了怎样的工作？如果给不熟悉它的人看，我会先推荐同一个任务作对照；你心里更接近哪种效果，或者想混合哪两种？”

收到回答后，再问由该方向引出的受众、素材或深度问题，结合已有信息形成简报；时长、平台和声音建议在需要时提出，不立即默认两分钟并开始配音。用户若给出具体资料，以上方向必须重做以匹配资料，不能照搬此表。

## 媒体能力与选择范围

按[17号](17-能力检查生图验收与偏好.md)只检查本次需要的声音/图片条件；已有口播或原图直接沿用。能力状态不放行文案、生成或云端上传，配置存在不代表账号可用。先使用用户本次已给选择和项目/用户偏好，不为了填写配置重复提问；平台改变须清掉另一平台音色绑定，补齐本次真实音色选择。普通选项只留本次，明确“记住/以后默认”才写长期偏好。只导入角色、纯风格研究不启动声音关卡；纯代码静帧不启动生图流程。新生图技术验收后仍按相应样稿关卡检查身份和视觉。
